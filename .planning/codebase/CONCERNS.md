# Codebase Concerns

**Analysis Date:** 2026-08-11

## Tech Debt

**Unreplaced create-next-app scaffold:**
- Issue: The only application route renders the stock Next.js onboarding screen, while the document title, description, repository package name, and public assets remain template values.
- Files: `src/app/page.tsx`, `src/app/layout.tsx`, `public/next.svg`, `public/vercel.svg`, `public/globe.svg`, `public/file.svg`, `public/window.svg`, `README.md`, `package.json`
- Impact: The deployed site does not provide Antigua's bake-and-cuisine content, navigation, menu, contact, ordering, or brand identity; visitors are sent to Next.js and Vercel resources instead.
- Fix approach: Replace the page with the approved business experience, replace or remove template assets, set production metadata in `src/app/layout.tsx`, and rewrite `README.md` around the actual project workflows.

**Typography has competing sources of truth:**
- Issue: `src/app/layout.tsx` loads Geist and exposes it through CSS variables, while `src/app/globals.css` directly sets the body to Arial/Helvetica; only elements explicitly using Tailwind's `font-sans` receive the configured Geist font.
- Files: `src/app/layout.tsx`, `src/app/globals.css`, `src/app/page.tsx`
- Impact: New content can render with inconsistent typography depending on whether the author remembers `font-sans`.
- Fix approach: Choose the site font intentionally and apply it through the `body` base style or Tailwind theme; remove the unused competing font setup.

**Installation/runtime contract is incomplete:**
- Issue: The project pins the installed dependency graph with `package-lock.json` but does not declare a Node.js version or package-manager version in `package.json`, `.nvmrc`, or a similar tracked configuration file.
- Files: `package.json`, `package-lock.json`
- Impact: Developer machines and deployment builders can use incompatible runtime versions for Next.js 16 and produce non-reproducible install/build behavior.
- Fix approach: Declare supported Node and npm versions in `package.json` (`engines` and optionally `packageManager`), commit the selected runtime file if used by the hosting platform, and document the requirement in `README.md`.

**Working tree dependency drift:**
- Issue: `npm ls --depth=0` reports six extraneous installed packages (`@emnapi/core`, `@emnapi/runtime`, `@emnapi/wasi-threads`, `@img/sharp-wasm32`, `@napi-rs/wasm-runtime`, and `@tybys/wasm-util`) even though related entries exist in the lockfile.
- Files: `package-lock.json`, `node_modules/@emnapi/core`, `node_modules/@emnapi/runtime`, `node_modules/@emnapi/wasi-threads`, `node_modules/@img/sharp-wasm32`, `node_modules/@napi-rs/wasm-runtime`, `node_modules/@tybys/wasm-util`
- Impact: Local dependency resolution is not clean, which can conceal platform-specific image-processing dependency problems and makes local diagnostics less trustworthy.
- Fix approach: Remove `node_modules` and reinstall with `npm ci`; investigate and correct lockfile/package-manager platform handling only if a clean install still reports the packages as extraneous.

- Files: `src/app/page.tsx`, `src/app/layout.tsx`
- Trigger: Visit the production or development root route.
- Workaround: None in the application; the route needs implementation.

**Generic page metadata is published:**
- Symptoms: Browser tabs and search previews use “Create Next App” and “Generated by create next app.” No route-level metadata, social metadata, manifest, sitemap, or robots configuration is present.
- Files: `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/favicon.ico`
- Trigger: Load `/` or allow a crawler/social preview service to inspect it.
- Workaround: None in the application; update metadata before sharing or indexing the site.

## Security Considerations

**No application security-header policy:**
- Risk: `next.config.ts` exports no headers configuration, so the application has no repository-defined Content-Security-Policy, clickjacking protection, referrer policy, or permissions policy. This matters once real scripts, embeds, forms, analytics, or user-provided content are introduced.
- Files: `next.config.ts`, `src/app/layout.tsx`, `src/app/page.tsx`
- Current mitigation: The current route is static, contains no user input or server-side data access, and its external `target="_blank"` links include `rel="noopener noreferrer"` in `src/app/page.tsx`.
- Recommendations: Establish an explicit headers policy in `next.config.ts` or at the deployment edge before integrations are added; tighten the CSP to only the domains required by the finished site.

**Secret hygiene is configured but unverified by automation:**
- Risk: `.env*` and `*.pem` are ignored, but there is no tracked secret-scanning or CI configuration to prevent accidental credentials from entering commits as the application gains integrations.
- Files: `.gitignore`, `package.json`
- Current mitigation: `.gitignore` excludes `.env*` and `*.pem`; no environment file is present in the repository scan.
- Recommendations: Add CI secret scanning and a documented environment-variable template that names required keys without values when external services are introduced.

## Performance Bottlenecks

**No current runtime bottleneck detected:**
- Problem: The single route is statically prerendered and has no data fetching, client-side state, API routes, or third-party runtime scripts.
- Files: `src/app/page.tsx`, `src/app/layout.tsx`, `next.config.ts`
- Cause: Not applicable to the current implementation; `npm run build` reports `/` as a static route.
- Improvement path: Preserve static rendering for brochure content, use optimized `next/image` assets for future photography, and measure Core Web Vitals before adding client-side libraries or embeds.

## Fragile Areas

**Single-page implementation concentrates all future UI work:**
- Files: `src/app/page.tsx`, `src/app/globals.css`
- Why fragile: There are no components, content modules, routes, data models, or design tokens beyond two global colors. Adding a restaurant site directly to the 69-line route will couple layout, copy, assets, and interaction logic.
- Safe modification: Establish feature components under `src/` and keep `src/app/page.tsx` as route composition; define reusable tokens and responsive styles in `src/app/globals.css` or the Tailwind theme before duplicating classes.
- Test coverage: No test files, test runner, or test script exists in `package.json`.

**Template assets can be accidentally shipped as brand assets:**
- Files: `public/next.svg`, `public/vercel.svg`, `public/globe.svg`, `public/file.svg`, `public/window.svg`, `src/app/page.tsx`
- Why fragile: The public directory contains only generator assets, two of which are directly rendered by the route. Asset names do not communicate the eventual brand and there is no asset inventory.
- Safe modification: Replace referenced assets atomically with licensed, optimized brand assets and remove unreferenced generator files; verify image alternative text and rendered dimensions.
- Test coverage: No visual regression or route-content tests exist for `src/app/page.tsx`.

## Scaling Limits

**No service or data layer exists:**
- Current capacity: One static route (`/`) and the generated not-found route are built from `src/app/page.tsx`; there are no API routes, database clients, queues, or caching implementations.
- Limit: The current structure cannot support menu management, reservations, orders, customer data, or other mutable business workflows without new persistence, validation, authentication, and operational design.
- Scaling path: Select managed services appropriate to the intended workflows, isolate them behind server-side modules and route handlers, validate all input, and add observability and integration tests before collecting customer data.

## Dependencies at Risk

**Version ranges for tooling allow incidental upgrades:**
- Risk: Tailwind, TypeScript, ESLint, React type packages, and the PostCSS plugin use broad major-version ranges in `package.json`.
- Impact: The lockfile makes current installs deterministic, but regenerating it can introduce behavior changes across major releases and can break styles, linting, or types unexpectedly.
- Migration plan: Keep `package-lock.json` committed, update these dependencies deliberately in reviewed batches, and run `npm run lint`, `npm run build`, and future tests after each update.
- Files: `package.json`, `package-lock.json`, `postcss.config.mjs`, `eslint.config.mjs`, `tsconfig.json`

## Missing Critical Features

- Blocks: The static generator screen in `src/app/page.tsx` cannot serve visitors, represent the business, or support any customer action.
- Files: `src/app/page.tsx`, `src/app/layout.tsx`, `public/`

**Deployment and operational automation are not defined:**

- Blocks: There is no repeatable repository-defined quality gate or operational feedback loop for releases.
- Files: `package.json`, `next.config.ts`, `README.md`

## Test Coverage Gaps

**Entire application route is untested:**
- What's not tested: Rendering of `/`, metadata, responsive behavior, keyboard accessibility, external-link safety, image alternative text, and future business flows.
- Files: `src/app/page.tsx`, `src/app/layout.tsx`, `package.json`, `eslint.config.mjs`
- Risk: The current lint and production-build checks pass, but they do not assert user-visible content, accessibility, or regressions.
- Priority: High once the placeholder route is replaced; establish unit/component tests and an end-to-end smoke test alongside the first real feature.

**No automated quality pipeline exists:**
- What's not tested: There is no test command, coverage command, test configuration, or continuous-integration workflow for the code in `src/app/`.
- Files: `package.json`, `src/app/page.tsx`, `src/app/layout.tsx`, `src/app/globals.css`
- Risk: Quality checks depend on a developer manually running `npm run lint` and `npm run build`; behavior and accessibility regressions can reach deployment undetected.
- Priority: High before production release; add a CI workflow that runs lint, build, and the selected test suite on every change.
