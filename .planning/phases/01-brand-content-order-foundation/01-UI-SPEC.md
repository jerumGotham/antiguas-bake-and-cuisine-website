# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui |
| Preset | `b2aAPYLnpA`; retain its Base Nova component conventions, but replace its stock stone/amber semantic values with the approved Antigua palette below. |
| Component library | Base UI (`@base-ui/react`) through shadcn/ui |
| Icon library | Lucide; use only where an icon improves comprehension (the mobile-menu trigger). Do not pair the primary CTA with an icon. |
| Font | `Playfair Display` for display/headings and `Inter` for all body, navigation, labels, buttons, and placeholders. Load with `next/font/google`; no remote font stylesheet. |

Use the installed shadcn `Button` as the base for shared buttons. Build the public header, footer, order CTA, card, section, and placeholders as project primitives; do not install additional UI packages or shadcn blocks in this phase. Preserve a server-rendered shared shell and isolate mobile-menu state in one client leaf.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, fine-rule offsets |
| sm | 8px | Label-to-control gaps, compact internal padding |
| md | 16px | Default control/card padding and element spacing |
| lg | 24px | Card gaps and compact section padding |
| xl | 32px | Desktop header padding and standard section gaps |
| 2xl | 48px | Mobile section vertical padding and major component separation |
| 3xl | 64px | Desktop section vertical padding and page-level separation |

Exceptions: interactive controls, including the mobile-menu trigger and header order CTA, have a minimum 44px by 44px target; horizontal page gutters are 16px on small screens and 32px from 768px upward.

---

## Typography

Use exactly these four sizes and two weights. Do not introduce a third weight for visual hierarchy; use size, font family, color, and spacing instead.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Headings and the wordmark use the serif display family. Body text, nav links, buttons, CTA support text, and placeholders use the sans family. Keep body measure to 65 characters or less where paragraphs are introduced in later phases.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Warm Cream `#F7F0D8` | Page background and primary public surfaces |
| Secondary (30%) | Soft Beige `#E8DCC1` | Header, footer, cards, image-placeholder fill, and muted section surfaces |
| Accent (10%) | Caramel `#C99A62` | Filled primary order CTA, active-nav indicator, small ornamental rules, and visible focus-ring outer color |
| Destructive | `#B42318` | Reserved for destructive actions and invalid/error states only; no destructive action ships in Phase 1 |

Supporting palette tokens: Chocolate Brown `#6B4328` is the default interactive/heading color; Dark Brown `#211814` is default body text and CTA foreground. Never use caramel as small text on cream or beige. Verify text/background contrast at implementation.

Accent reserved for: the filled **“Message us on Facebook.”** CTA, the current Home indicator, decorative separators, and focus-ring outer color. It is not a general link or hover color.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Message us on Facebook.` |
| CTA support text | `Facebook login may be required to message us.` |
| Missing factual field | `Details coming soon.` |
| Missing image label | `Image coming soon` |
| Empty state heading | `Image coming soon` |
| Empty state body | `Details coming soon.` Render this branded placeholder instead of stock food imagery whenever an expected approved image is absent. |
| Error state | No in-app loading, form submission, or recoverable external-link error state exists in Phase 1. The Facebook Page opens in a new tab; the browser/Facebook owns any failure. Do not claim that a message was sent or an order was received. |
| Destructive confirmation | None — no destructive action is in scope. |

The CTA must be a normal external anchor to the single configured URL `https://www.facebook.com/antiguasbakeandcuisine`, open in a new tab with `rel="noopener noreferrer"`. Do not call it a direct Messenger link, create a deep link, or add a product prefill. Render the support text directly adjacent to every primary CTA. Expected-but-unapproved business or product facts render the exact factual placeholder; optional facts without an expected visual slot are omitted. Never invent facts, claims, prices, images, or availability.

## UI Considerations

### Primary-Screen Hierarchy

On the primary public screen, guide the eye in this exact order: **(1)** the Antigua’s Bake & Cuisine wordmark, **(2)** the filled **“Message us on Facebook.”** CTA with its adjacent login support text, and **(3)** supporting Home content and factual/image placeholders. Keep the wordmark as the header’s strongest identity element; make the CTA the only filled accent control; subordinate all supporting text through the documented body/label styles and secondary color surfaces. At every viewport width, do not let navigation, decorative rules, or placeholders compete with the wordmark or CTA.

Applicable state considerations resolved: 7 covered, 8 dismissed, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Branded product-image placeholder | ✅ covered | An absent or unapproved expected image renders the documented `Image coming soon` label and `Details coming soon.` body; no stock image is substituted. |
| populated | Product-image primitive | ✅ covered | When an owner-approved local image is supplied, render it with meaningful supplied alt text; otherwise use the branded placeholder. |
| loading | Product-image primitive | ✅ dismissed | Phase 1 ships static local content only; no client data fetch or image-progress UI is in scope. |
| error | Product-image primitive | ✅ covered | An absent, unapproved, or unusable approved-image value falls back to the branded image placeholder, never a fabricated substitute. |
| long-text | Placeholder text and future factual values | 🧪 backstop | Long values wrap within their card/section without clipping, overlapping, or horizontal page scrolling. |
| nav | Header navigation and mobile-menu panel | ✅ covered | Show only Home and the distinct primary order action. The mobile trigger exposes `aria-expanded`; Escape closes the panel; Home activation closes it; focus remains visible. |
| loading | Navigation and mobile-menu trigger | ✅ dismissed | Internal Home navigation is framework navigation and the panel is local synchronous state; no custom loading state is introduced. |
| error | Navigation and mobile-menu trigger | ✅ dismissed | The public shell has no remote navigation data or recoverable menu request. |
| overflow | Header navigation and mobile-menu panel | ✅ covered | Desktop header uses a single Home link plus CTA; on narrow screens, navigation collapses to the compact panel while brand and CTA remain prominent. |
| long-text | Brand name, Home link, CTA, and support text | ✅ covered | Text wraps rather than truncates; the CTA may grow vertically while retaining its 44px minimum target and the support text stays readable below it. |
| interactive-control | Primary order CTA | ✅ covered | Use native anchor semantics, visible focus, gentle color/shadow feedback on hover, and a 1px pressed translation only; honor `prefers-reduced-motion` by removing transition/transform motion. |
| loading | Primary order CTA | ✅ dismissed | The anchor opens the configured Facebook Page in a separate browser tab; the app cannot reliably observe Facebook authentication or page-load status. |
| error | Primary order CTA | ✅ dismissed | Do not render a false success/error message for an external handoff; the fixed support text truthfully sets the login expectation. |
| long-text | Footer brand note and factual placeholder content | 🧪 backstop | Long owner-approved or placeholder text wraps, preserves all words, and does not create viewport overflow at 320px. |
| overflow | Footer and static content | ✅ covered | Footer stacks vertically on small screens and uses 16px minimum gutters; no future sitemap/contact list is shown. |
| partial | Business/product factual displays | ✅ covered | Render `Details coming soon.` for each expected missing fact and the branded image placeholder for missing imagery; omit optional fields lacking an expected slot. |
